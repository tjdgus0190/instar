# 1일 1상품 파이프라인

`CLAUDE.md`의 목표·제약·기술 스택을 따른다. 각 단계는 해당 서브에이전트(`.claude/agents/`)에게 맡기고, 메인 세션은 진행 관리와 산출물 전달만 한다.
인자로 주제/키워드가 주어지면 1단계 후보를 그 주제 안에서 찾는다.

## 0. 준비
- 오늘 날짜(YYYY-MM-DD)를 확인한다.
- `ops/ledger.md`, `ops/decisions.md`, `playbook/references.md`를 읽어 과거 성과와 매출 난 패턴을 파악한다.

## 1. 아이디어 3안 — `planner` → `marketer`
- planner: 레퍼런스 근거를 붙인 후보 3안.
- marketer: 같은 3안에 대해 수요 검증(실제 판매 근거, 검색/커뮤니티 수요, 가격 제안)을 덧붙인다.

## 2. 아이디어 승인 — `ceo`
- 100점 척도 채점. 70점 미만이면 반려 사유를 planner에게 전달해 1단계 재실행(최대 2회).
- 3회째도 미달이면 최고점 안을 범위 축소 조건부로 승인하거나, 매출 난 기존 서비스의 변형으로 대체한다.

## 3. 범위 확정 — `planner`
- `services/<날짜>-<slug>/brief.md` 작성 (`templates/brief.md`).

## 4. 디자인 — `designer`
- `design.md` 작성 (`templates/design.md`).

## 5. 구현 — `developer`
- `app/`에 구현, 결제/광고/분석 연동, 로컬 빌드·실행 확인.

## 6. 검증 — `qa`
- `qa.md` 작성. Blocker가 있으면 developer에게 반환 → 수정 → 재검증 반복.

## 7. 배포 승인 — `ceo`
- 승인 시 developer가 배포(웹 배포·스토어 제출·Gumroad 상품 업로드)하고 URL을 기록. 배포 자격 증명이 없으면 배포 명령과 필요한 설정을 정리해 사용자에게 요청한다.

## 8. 런칭 — `marketer`
- `launch.md` 작성, SEO 산출물·채널별 게시 문구·OG 이미지 준비.
- 외부 게시(커뮤니티 글 작성 등)는 사용자 확인 후에만 한다.

## 9. 기록 — `ceo`
- `ops/ledger.md`에 서비스 행 추가, `ops/decisions.md`에 결정 기록.
- 변경 사항을 커밋한다: `feat(<slug>): <한 줄 요약>`.

## 마무리 보고 (사용자에게)
- 서비스명/URL, 수익 모델과 가격, 레퍼런스, 사용자가 직접 해야 할 일(결제 계정 연결, 광고 심사 신청, 도메인 등)을 5줄 이내로.
