# 웹 외 상품 배포·판매 가이드

> 스토어 정책·심사 기간·비용은 자주 바뀐다. 연동 전 공식 문서를 다시 확인하고 확인일을 적는다.

## 형태별 비교

| 형태 | 설치 마찰 | 판매 경로 | 1일 출시 리스크 |
|---|---|---|---|
| 스크립트·시트·템플릿 | 없음(파일 열기) | Gumroad 파일 판매 | 낮음 |
| 크롬 확장 | 낮음(클릭 설치) | 스토어 무료 배포 + Gumroad/Lemon Squeezy 라이선스 | 스토어 심사 대기 |
| 데스크톱 프로그램 | 높음(다운로드·경고) | Gumroad/Lemon Squeezy 다운로드 + 라이선스 | 서명·오탐·OS별 빌드 |
| 봇 | 낮음 | 결제 링크 + 서버 권한 부여 | 낮음 |

## 크롬 확장
- 개발자 등록(1회 등록비) 후 개인으로 게시 가능.
- 스토어 내 결제 기능은 없음 → 결제는 외부(Gumroad/Lemon Squeezy)에서 하고 확장 안에서 라이선스 키로 해제.
- 심사: 권한이 넓을수록, 원격 코드가 있을수록 지연·거절. 첫 심사는 수일 걸릴 수 있다 → 심사 중에는 판매 랜딩과 대기자 수집(이메일)으로 시작.
- 개인정보 처리 공개 항목(데이터 사용 공개)을 정확히 작성.

## 데스크톱 프로그램
- **Windows**: 코드 서명이 없으면 SmartScreen "알 수 없는 게시자" 경고. 인증서는 비용이 들고 발급 조건(개인/사업자)이 상품마다 다르다 → 매출 검증 전에는 서명 없이 출시하고 FAQ에 실행 방법 안내, 매출이 나면 서명 도입 검토.
- **macOS**: 공증(notarization)을 위해 Apple Developer Program(연회비, 개인 가입 가능) 필요. 공증 없으면 Gatekeeper 차단 → 맥 버전은 매출 검증 후로 미루는 것도 선택지.
- PyInstaller 등 패키저는 백신 오탐이 잦다 → 출시 전 VirusTotal로 확인, 가능하면 Tauri 사용.
- 빌드는 GitHub Actions에서 OS별로. 바이너리는 저장소에 커밋하지 않고 Gumroad/Lemon Squeezy 상품 파일로 업로드.

## 스크립트·시트·템플릿
- 엑셀 매크로 파일(.xlsm)은 열 때 보안 경고 → "콘텐츠 사용" 안내 이미지를 첫 시트에 둔다.
- 구글 시트는 "사본 만들기" 링크 방식으로 전달하면 가장 간단하다.
- 상품에 사용 설명서, 버전, 문의 경로를 포함.

## 라이선스 키 공통 흐름
1. 판매 페이지에서 Gumroad/Lemon Squeezy 결제 → 키 자동 발급(이메일).
2. 앱/확장에서 키 입력 → 판매처 License API로 검증 → 성공 시 로컬 저장.
3. 주기적 재검증(예: 7일), 오프라인 유예 허용, 환불·취소 키는 다음 검증 때 차단.
4. 무료 체험 한도(횟수/기능)를 두고 한도 도달 시 구매 안내.
