## 5. 사용자 흐름

1. **유입**: Show GN / 클리앙 / 디스콰이엇 / 검색 → 계산기 페이지(`/`) 도착 (`page_view`, UTM 보존)
2. **첫 가치 경험(30초 이내)**: 입력 4칸(총급여, 지금까지 신용카드, 지금까지 체크+현금, 11~12월 예상 지출) + 선택 2칸(전통시장·대중교통, 자녀 수) → [계산] → "25% 문턱까지 남은 금액", "신용카드로 쓸 때 vs 체크카드로 쓸 때 공제액, 차이 +N원" 표시 (`calc_complete`). 입력값은 브라우저 안에서만 계산.
3. **결제 노출**: 결과 바로 아래 시트 CTA → 판매 섹션(`/#sheet` 또는 `/sheet`) → Gumroad 버튼(`checkout_click`) + 고정 문구 "$6.99(약 1만원), 달러 청구, 해외결제 가능한 Visa/Master 카드 필요"
4. **결과 전달**: Gumroad 결제 → Gumroad가 자동으로 설명 PDF(사본 만들기 링크 포함) 전달 → 구매자가 "사본 만들기"로 본인 드라이브에 시트 생성. Gumroad Ping → Pages Function이 `purchase` 기록.
- 회원가입 없음. 첫 가치 경험 전 이메일 요구 없음.

## 6. MVP 기능 (3개, 완료 조건 포함)

- [ ] **기능 1 — 무료 웹 계산기 "남은 두 달, 체크카드로 바꿔야 할까" (2026 현행 규칙)**
  - 완료 조건 1: 부록 C의 검증 케이스 1~4를 입력하면 화면 출력값이 기대값과 **원 단위까지 일치**한다.
  - 완료 조건 2: 브라우저 개발자도구 네트워크 탭에서 [계산] 클릭 전후로 입력값(총급여·사용액·자녀 수)이 담긴 요청이 **0건**이다. 분석 이벤트 파라미터에도 입력값·결과 금액이 없다. URL 쿼리·해시에도 입력값이 남지 않는다.
  - 완료 조건 3: [결과 복사] 버튼은 텍스트만 클립보드에 복사한다(예: "남은 지출을 체크카드로 쓰면 카드공제가 약 52만원 늘어요 — <계산기 URL>"). 총급여·사용액 원값은 포함하지 않는다. 이미지 생성 없음.
  - 완료 조건 4: 결과 영역에 고정 면책 문구와 "소비증가분 특례·문화비 별도 공제율·종합한도는 계산에 포함하지 않음" 안내가 보인다.
  - 완료 조건 5: 모바일(375px 폭)에서 입력~결과까지 가로 스크롤 없이 동작한다.
- [ ] **기능 2 — 유료 구글 시트 패키지 ($6.99, 부록 D 구성 ①~④)**
  - 완료 조건 1: 시트 ① "2026 마무리" 탭에 부록 C 케이스 1~4를 넣으면 계산기와 **동일한 값**이 나온다.
  - 완료 조건 2: ③ 2027 공제 탭의 기본값은 현행 규칙이며, 시나리오 토글을 켰을 때만 개정안 값으로 바뀌고, 토글 옆에 "정부 개정안(국회 미통과) — 미확정 시나리오" 표기가 보인다.
  - 완료 조건 3: 설명 PDF의 "사본 만들기" 링크(`/copy` URL)를 로그인한 다른 구글 계정으로 열면 사본이 생성되고 수식 오류(#REF!, #ERROR!) 0개.
  - 완료 조건 4: xlsx 내보내기 후 엑셀에서 열어 부록 C 케이스 값이 같으면 엑셀 사본 포함, 하나라도 깨지면 **엑셀 사본 제외 + 상품 설명에서 "엑셀" 문구 삭제**.
- [ ] **기능 3 — 판매 랜딩 + 측정 (Cloudflare Pages 정적 + Pages Function 1개)**
  - 완료 조건 1: 페이지 존재 — 계산기(`/`), 2027 개정안 정보(`/2027-card-deduction-changes`), 시트 판매 섹션, 개인정보처리방침·이용약관·환불정책·면책 페이지. 각 페이지에 title/description/OG, `sitemap.xml`, `robots.txt`.
  - 완료 조건 2: `page_view`, `calc_complete`, `checkout_click`이 분석 도구에 기록되고, Gumroad 테스트 결제(본인 구매 또는 100% 할인 코드) 1건이 `purchase`로 Pages Function 로그/저장소에 기록된다(운영자 계정 연결 후 검증, 게이트 2 전 필수).
  - 완료 조건 3: 결제 버튼 옆 고정 문구가 부록 F 원문과 글자 단위로 같다. 개정안 관련 문장에 "확정", "사라진다", "폐지 확정" 단정 표현이 0개이고, 모두 "정부 개정안대로 통과되면" 또는 "미확정"이 붙는다.
  - 완료 조건 4: Gumroad 버튼 링크와 랜딩 공유 링크에 UTM(`utm_source`, `utm_medium`, `utm_campaign`)이 유지된다.

- 시트 사본 링크 무단 공유(감수, 시트 하단에 구매자용 표기만).

## 부록 B. 계산 로직 명세 (계산기·시트 ① 공통, 2026 현행)

### B-1. 입력 (무료 계산기)

| 키 | 라벨 | 필수 | 단위·검증 |
|---|---|---|---|
| `G` | 올해 총급여(연봉에서 비과세 제외, 모르면 연봉) | 필수 | 원, 정수, 1 ~ 10,000,000,000 |
| `C` | 지금까지 신용카드 사용액 (홈택스 미리보기 1~9월 + 10월 사용분, **전통시장·대중교통 제외**) | 필수 | 원, ≥ 0 |
| `D` | 지금까지 체크카드 + 현금영수증 사용액 (같은 기준, 전통시장·대중교통 제외) | 필수 | 원, ≥ 0 |
| `X` | 11~12월 예상 지출 | 필수 | 원, ≥ 0 |
| `T` | 지금까지 전통시장 + 대중교통 사용액(결제수단 무관 합계) | 선택, 기본 0 | 원, ≥ 0 |
| `K` | 20세 이하 자녀·손자녀 수 (소득 요건 충족, 다른 사람이 기본공제 받지 않는 경우만 — A-1 #10) | 선택, 기본 0 | 0 / 1 / 2명 이상 |

- 단순화 근거: 2026 현행에서 전통시장·대중교통은 둘 다 40%이고 같은 추가공제 바구니라 합산해도 결과가 같다(A-1 #4·#5·#11).
- **문화비(도서·공연·영화·체육시설)는 범위 밖**. 안내: "문화비는 실제 결제수단 칸(신용/체크)에 포함해 입력하세요. 총급여 7천만원 이하인 경우 신용카드로 결제한 문화비는 실제보다 공제가 적게 계산될 수 있습니다." (보수적 과소 추정)
- `X`는 전통시장·대중교통이 아닌 일반 지출로 가정한다.

### B-2. 핵심 함수 (의사코드, 모든 금액 원 단위 정수)

```
// 공제율은 % 정수, 곱셈 후 100으로 나눔(소수 원은 마지막에만 내림)
RATE_CREDIT = 15; RATE_DEBIT = 30; RATE_MARKET_TRANSIT = 40
LIMIT_SPLIT = 70_000_000        // 총급여 7천만원 "이하" 판정

function basicLimit(G, K):
    k = min(K, 2)
    if G <= LIMIT_SPLIT: return 3_000_000 + k * 500_000
    else:                return 2_500_000 + k * 250_000

function extraLimit(G):
    return (G <= LIMIT_SPLIT) ? 3_000_000 : 2_000_000

function deduction(G, C, D, T, K):           // 반환: 소득공제액(원), 정수
    M = G * 25 / 100                          // 최저사용금액 (소수 유지)
    total = C + D + T
    if total <= M: return 0

    gross = (C*15 + D*30 + T*40) / 100

    // 최저사용금액 차감액: 공제율 낮은 바구니부터 채운다(국세청 안내 A-1 #7)
    if C >= M:
        sub = M*15/100
    else if C + D >= M:
        sub = C*15/100 + (M - C)*30/100
    else:
        sub = C*15/100 + D*30/100 + (M - C - D)*40/100

    base = gross - sub                         // 일반 공제대상금액 (>= 0)
    BL = basicLimit(G, K)
    if base <= BL:
        return floor(base)

    // 기본한도 초과분은 추가공제 대상(전통시장·대중교통 사용분 × 40%)과 추가한도 중 작은 값까지
    extra = min(base - BL, T*40/100, extraLimit(G))
    return floor(BL + extra)
```

※ 실제 결제 시점 순서는 무관하다. 최저사용금액은 결제 순서가 아니라 **공제율 낮은 결제수단부터** 차감하므로, "문턱까지 신용카드, 이후 체크카드"를 시간 순으로 지키지 않아도 세법상 공제액은 같다. (신용카드 혜택·실적 조건 때문에 그 순서를 권하는 것일 뿐 — 계산기 FAQ에 넣는다.)

### B-3. 계산기 출력

```
M = G*25/100
remainingNow   = max(0, M - (C + D + T))                 // "25% 문턱까지 남은 금액(현재)"
remainingAfter = max(0, M - (C + D + T + X))             // "11~12월 지출 후에도 남는 금액"
A = deduction(G, C + X, D, T, K)                         // 남은 지출을 신용카드로
B = deduction(G, C, D + X, T, K)                         // 남은 지출을 체크카드·현금영수증으로
diff = B - A                                             // 항상 >= 0
```

출력 문구 규칙(우선순위 순):
1. `remainingAfter > 0` → "11~12월 지출을 다 써도 25% 문턱에 {remainingAfter}원 못 미칩니다. 문턱 아래 지출은 결제수단과 상관없이 공제가 없어요." (diff = 0)
2. `diff == 0` 그리고 `A >= basicLimit(G,K)` → "이미 공제 한도에 도달해 체크카드로 바꿔도 공제액이 같습니다. 혜택 좋은 신용카드를 쓰세요."
2-1. `diff == 0` (위 둘에 해당하지 않음) → "남은 지출은 대부분 25% 문턱을 채우는 데 쓰여 결제수단에 따른 차이가 없습니다." (`result_type = zero_diff`, 부록 C 케이스 2)
3. 그 외 → "남은 {X}원을 체크카드·현금영수증으로 쓰면 소득공제가 {diff}원 늘어납니다 (신용 {A}원 → 체크 {B}원)."
- 공통 보조 문구: "소득공제액 기준입니다. 실제 줄어드는 세금은 공제액 × 본인 세율(지방소득세 포함)이라 이보다 작습니다." + 면책 고정 문구 + "소비증가분 특례·문화비 별도 공제율·종합한도는 계산에 포함하지 않음".
- 결과 복사 텍스트: 규칙 3이면 "남은 지출을 체크카드로 쓰면 카드 소득공제가 약 {diff를 만원 단위 반올림}만원 늘어요 — {URL}", 그 외 "카드공제 문턱·한도 30초 계산 — {URL}". 입력값 미포함.

### B-4. 시트 전용 확장 (시트 ①·③)
- 문화체육 사용분 `S` 입력칸 추가: 7천만원 이하면 공제율 30%, 차감 순서 ②단계(체크와 같은 바구니), 추가공제 대상에 `S*30/100` 합산. 7천만원 초과면 `S`는 결제수단 칸으로 안내(별도 공제율 없음).
- 전통시장·대중교통은 별도 칸(`TM`, `TT`)으로 받되 현행 계산은 `T = TM + TT`.
- 시트 ③ 시나리오 토글 ON(개정안, A-2): `TT`는 결제수단 칸으로 재분류(신용 15%/체크 30% — 시트는 대중교통 결제수단 열을 추가로 받음), 추가공제 대상에서 제외, 문화체육 30%를 총급여 무관 적용, 추가한도 200만/100만원. 기본한도·자녀 가산·최저사용금액·기본 공제율은 현행 유지.

## 부록 C. QA 검증 케이스 (손계산, 계산기·시트 ①이 원 단위로 일치해야 함)

국세청·정부 자료에서 숫자를 넣은 공식 계산 예시는 찾지 못했다(국세청 안내 2건 모두 산식만 제공, 2026-10-26). 따라서 아래 기대값은 A-1 산식 기준 손계산이다. QA는 홈택스 '연말정산 미리보기'·'모의계산'이 열리면 케이스 1을 넣어 신용카드 공제액 칸을 대조하고 결과를 `qa.md`에 남긴다(가능할 때).

### 케이스 1 — 문턱 통과, 전환 이득 발생 (핵심 시나리오)
입력: G = 50,000,000 / C = 12,000,000 / D = 3,000,000 / T = 0 / K = 0 / X = 4,000,000
- M = 50,000,000 × 25% = 12,500,000. remainingNow = 12,500,000 − 15,000,000 → **0**. remainingAfter **0**.
- A(신용): C = 16,000,000, D = 3,000,000
  - gross = 16,000,000×15% + 3,000,000×30% = 2,400,000 + 900,000 = 3,300,000
  - C ≥ M → sub = 12,500,000×15% = 1,875,000
  - base = 1,425,000 ≤ 기본한도 3,000,000 → **A = 1,425,000원**
- B(체크): C = 12,000,000, D = 7,000,000
  - gross = 1,800,000 + 2,100,000 = 3,900,000
  - C < M ≤ C+D → sub = 12,000,000×15% + 500,000×30% = 1,800,000 + 150,000 = 1,950,000
  - base = 1,950,000 → **B = 1,950,000원**
- **diff = 525,000원** (검산: 4,000,000 중 문턱을 넘는 3,500,000 × (30% − 15%) = 525,000). 출력 규칙 3.

### 케이스 2 — 지출 후에도 문턱 근처, 전환 이득 0 (차감 순서 검증)
입력: G = 40,000,000 / C = 6,000,000 / D = 1,000,000 / T = 500,000 / K = 0 / X = 3,000,000
- M = 10,000,000. remainingNow = 10,000,000 − 7,500,000 = **2,500,000원**. remainingAfter = 10,000,000 − 10,500,000 → 0.
- A: C = 9,000,000, D = 1,000,000, T = 500,000
  - gross = 1,350,000 + 300,000 + 200,000 = 1,850,000
  - C < M, C + D = 10,000,000 ≥ M → sub = 1,350,000 + 1,000,000×30% = 1,650,000
  - base = 200,000 → **A = 200,000원**
- B: C = 6,000,000, D = 4,000,000, T = 500,000
  - gross = 900,000 + 1,200,000 + 200,000 = 2,300,000
  - sub = 900,000 + 4,000,000×30% = 2,100,000
  - base = 200,000 → **B = 200,000원**
- **diff = 0원**. 신용+체크가 정확히 문턱을 채우고 넘는 부분은 전통시장·대중교통(40%) 50만원뿐이라 결제수단 전환 효과가 없다. 출력: B-3 규칙 2-1 문구(`zero_diff`). 규칙 3의 "0원 늘어납니다"가 나오면 실패. 화면에 remainingNow 2,500,000원 표시.

### 케이스 3 — 7천만원 초과 + 자녀 1명 + 한도 포화 (한도·추가한도 검증)
입력: G = 80,000,000 / C = 30,000,000 / D = 10,000,000 / T = 2,000,000 / K = 1 / X = 5,000,000
- M = 20,000,000. remainingNow 0.
- 기본한도 = 2,500,000 + 250,000 = 2,750,000. 추가한도 = 2,000,000. 추가공제 대상 = 2,000,000×40% = 800,000.
- A: C = 35,000,000 → gross = 5,250,000 + 3,000,000 + 800,000 = 9,050,000, sub = 20,000,000×15% = 3,000,000, base = 6,050,000 > 2,750,000 → extra = min(3,300,000, 800,000, 2,000,000) = 800,000 → **A = 3,550,000원**
- B: D = 15,000,000 → gross = 4,500,000 + 4,500,000 + 800,000 = 9,800,000, sub = 3,000,000, base = 6,800,000 → extra = 800,000 → **B = 3,550,000원**
- **diff = 0원**, 출력 규칙 2(한도 도달). K = 0으로 바꾸면 A = B = 2,500,000 + 800,000 = 3,300,000원(자녀 가산 25만원 반영 확인용).

### 케이스 4 (경계) — 총급여 정확히 70,000,000원
입력: G = 70,000,000 / C = 40,000,000 / D = 0 / T = 0 / K = 0 / X = 0 → M = 17,500,000, base = (40,000,000 − 17,500,000)×15% = 3,375,000 → "이하" 구간 기본한도 3,000,000 적용 → **3,000,000원** (G = 70,000,001이면 2,500,000원).
