#### 숫자 입력 UX (금액 칸 5개 공통)

```html
<label for="in-g">올해 총급여 <span class="badge">필수</span></label>
<div class="money">
  <input id="in-g" type="text" inputmode="numeric" pattern="[0-9,]*"
         autocomplete="off" enterkeyhint="next" maxlength="14"
         placeholder="예: 50,000,000" aria-describedby="in-g-man in-g-help in-g-err">
  <span class="money-unit" aria-hidden="true">원</span>
</div>
<p id="in-g-man" class="man" aria-live="off"></p>
<p id="in-g-help" class="help">…</p>
<p id="in-g-err" class="err" hidden></p>
```

- `type="number"` 금지(콤마 불가, 스크롤 휠로 값 변경, iOS 키패드 불일치). `inputmode="numeric"`으로 모바일 숫자 키패드.
- 마지막 금액 칸(`X`, 또는 선택 칸이 열려 있으면 `T`)은 `enterkeyhint="done"`. 키패드 완료/엔터 → 다음 칸 포커스, 마지막 칸이면 계산 실행.
- **천 단위 콤마**: `input` 이벤트마다 숫자 외 문자 제거 → 앞자리 0 제거 → 최대 11자리(100억 = 11자리) → `Number(digits).toLocaleString('ko-KR')`로 재표시. 커서 위치는 "커서 앞의 숫자 개수"를 세어 포맷 후 같은 숫자 개수 뒤로 복원(콤마 삽입 때문에 커서가 끝으로 튀지 않게).
- 붙여넣기 "12,000,000원" → 숫자만 남겨 12,000,000. "5천만" 같은 한글 단위는 숫자만 남아 "5"가 되므로 아래 만원 표기로 사용자가 즉시 알아챈다(별도 파서 없음).
- **"만원" 보조 표기**(`.man`, 입력칸 바로 아래, 값이 있을 때만):
  - 1만 미만: "= 9,999원"
  - 1만 이상 1억 미만: "= 5,000만원" (만 미만 자투리 있으면 "= 약 1,234만원", 내림)
  - 1억 이상: "= 1억 2,500만원", 정확히 억 단위면 "= 2억원", 자투리 있으면 앞에 "약"
- 내부 값은 정수 원 단위 문자열 → `parseInt`. 빈 칸 = 미입력(선택 칸은 0으로 간주).
- 값은 `localStorage`·URL·쿼리·해시에 저장하지 않는다. 새로고침하면 사라진다(완료 조건 2). `autocomplete="off"`.

#### 검증·에러 (계산하기 클릭 시 판정, 입력 중에는 에러 지우기만)

| 조건 | 대상 | 메시지(확정) | 표시 |
|---|---|---|---|
| 필수 칸 비어 있음 | G, C, D, X | "금액을 입력해 주세요. 없으면 0을 넣으세요." (G는 "올해 총급여를 입력해 주세요.") | 칸 테두리 `--color-error`, `aria-invalid="true"`, 메시지 노출, 첫 에러 칸으로 포커스+스크롤 |
| G = 0 | G | "총급여는 1원 이상이어야 해요." | 동일 |
| G > 10,000,000,000 | G | "100억원 이하로 입력해 주세요." | 동일 |
| 금액 > 10,000,000,000 | C·D·X·T | "100억원 이하로 입력해 주세요." | 동일 |
| (경고, 계산은 진행) C+D+T+X > G | 결과 카드 상단 | "입력한 사용액 합계가 총급여보다 커요. 금액이 맞는지 한 번 확인해 주세요." | `--color-notice` 줄, 계산은 그대로 표시 |

- 칸을 다시 수정하면 그 칸의 에러를 즉시 제거.

### 2-5. 결과 카드 (규칙 1 / 2 / 2-1 / 3)

공통 구조(위→아래). `<section id="result" aria-live="polite" tabindex="-1">`. 계산 후 `scrollIntoView({block:'start', behavior:'smooth'})` + 헤딩에 포커스. `prefers-reduced-motion`이면 smooth 끔.

```
┌ 결과 ────────────────────────────────┐
│ [경고 줄 — C+D+T+X > G일 때만]              │
│ 〈아이브로우〉 13px muted                    │
│ 〈히어로 숫자〉 40px/800 tabular-nums         │
│ 〈히어로 보조〉 15px  (만원 환산 또는 짧은 해석) │
│ ─────────────────────────────────────  │
│ 〈규칙 문장〉 16px — 부록 B-3 문구 그대로        │
│ ─────────────────────────────────────  │
│ 공제액 비교                                 │
│ 신용카드로 쓸 때  ▓▓▓▓▓▓▓░░░░  1,425,000원    │  막대: --color-credit
│ 체크카드로 쓸 때  ▓▓▓▓▓▓▓▓▓▓░  1,950,000원    │  막대: --color-primary
│ ─────────────────────────────────────  │
│ 25% 문턱  12,500,000원                     │
│ [■■■■■■■■■■■■] 지금까지 15,000,000원 사용     │  진행 막대(최대 100%), 높이 10px
│ 문턱까지 남은 금액(지금): 0원 · 이미 넘었어요     │
│ 11~12월 지출 후에도 남는 금액: 0원              │
│ 공제 한도: 기본 3,000,000원                   │
│ ─────────────────────────────────────  │
│ [ 결과 복사 ]  (Secondary 버튼 48px)          │
│ ─────────────────────────────────────  │
│ 소득공제액 기준입니다. 실제 줄어드는 세금은       │  보조 문구 13px muted
│ 공제액 × 본인 세율(지방소득세 포함)이라 이보다     │
│ 작습니다.                                   │
│ 소비증가분 특례·문화비 별도 공제율·종합한도는     │
│ 계산에 포함하지 않음                          │
```

- 막대 폭: `max(A,B)`를 100%로. 둘 다 0이면 막대 대신 "두 경우 모두 공제 0원" 한 줄.
- 문턱 진행 막대: `min(1, (C+D+T)/M)`. 100%이면 막대 색 `--color-primary`, 미만이면 `--color-credit`.
- "공제 한도" 줄: `기본 {basicLimit}원`. T > 0이면 " · 전통시장·대중교통 추가 {extraLimit}원까지" 덧붙임.
- 모든 금액: `toLocaleString('ko-KR') + "원"`, `font-variant-numeric: tabular-nums`. 규칙 문장 안 금액은 원 단위 그대로(QA가 원 단위로 대조).
- 결과 영역에 총급여·사용액 원값을 화면에 보여 주는 것은 허용(로컬 표시). 복사 텍스트·이벤트에는 넣지 않는다.

#### 규칙별 표시 (우선순위: 1 → 2 → 2-1 → 3, `result_type`)

**규칙 1 (`rule1`)** — `remainingAfter > 0`

- 아이브로우: "아직 25% 문턱 아래예요"
- 히어로 숫자: `{remainingAfter}원` (색 `--color-text`)
- 히어로 보조: "11~12월 지출 후에도 문턱까지 남는 금액 (약 {만원}만원)"
- 규칙 문장: "11~12월 지출을 다 써도 25% 문턱에 {remainingAfter}원 못 미칩니다. 문턱 아래 지출은 결제수단과 상관없이 공제가 없어요."
- 비교 막대: 표시(대부분 둘 다 0원 → "두 경우 모두 공제 0원")

**규칙 2 (`rule2`)** — `diff == 0` 그리고 `A >= basicLimit`

- 아이브로우: "이미 공제 한도에 도달했어요"
- 히어로 숫자: `{A}원` (색 `--color-primary`)
- 히어로 보조: "예상 카드 소득공제 (기본 한도 {basicLimit}원)"
- 규칙 문장: "이미 공제 한도에 도달해 체크카드로 바꿔도 공제액이 같습니다. 혜택 좋은 신용카드를 쓰세요."
- 예: 케이스 3 → 3,550,000원, 기본 한도 2,750,000원

**규칙 2-1 (`zero_diff`)** — `diff == 0` (위 둘 아님)

- 아이브로우: "결제수단에 따른 차이가 없어요"
- 히어로 숫자: `0원` + 접두 없음 (색 `--color-text`)
- 히어로 보조: "신용카드로 써도, 체크카드로 써도 공제액 {A}원"
- 규칙 문장: "남은 지출은 대부분 25% 문턱을 채우는 데 쓰여 결제수단에 따른 차이가 없습니다."
- 문턱 블록의 "문턱까지 남은 금액(지금)"을 굵게 강조. 예: 케이스 2 → "문턱까지 남은 금액(지금): 2,500,000원"
- "0원 늘어납니다" 문구가 절대 나오면 안 됨.

**규칙 3 (`rule3`)** — 그 외(diff > 0)

- 아이브로우: "체크카드로 바꾸면"
- 히어로 숫자: `+{diff}원` (색 `--color-gain`)
- 히어로 보조: "소득공제가 늘어요 (약 {round(diff/10000)}만원)" — diff < 5,000이면 괄호 생략
- 규칙 문장: "남은 {X}원을 체크카드·현금영수증으로 쓰면 소득공제가 {diff}원 늘어납니다 (신용 {A}원 → 체크 {B}원)."
- 예: 케이스 1 → "+525,000원" / "남은 4,000,000원을 체크카드·현금영수증으로 쓰면 소득공제가 525,000원 늘어납니다 (신용 1,425,000원 → 체크 1,950,000원)."

#### 결과 복사

- 버튼 라벨: "결과 복사" → 성공 시 2초간 "복사했어요" (아이콘 체크) 후 원복.
- 텍스트:
  - 규칙 3이고 `round(diff/10000) >= 1`: "남은 지출을 체크카드로 쓰면 카드 소득공제가 약 {round(diff/10000)}만원 늘어요 — {URL}"
  - 그 외(규칙 1/2/2-1, 또는 반올림 0만원): "카드공제 문턱·한도 30초 계산 — {URL}"
  - `{URL}` = 정식 URL(`https://<도메인>/`), UTM·쿼리 없음.
  - 반올림은 `Math.round`(케이스 1 = 525,000 → "약 53만원"). ※ brief 6장 완료조건 3의 "약 52만원"은 예시 문장이고, 규칙은 부록 B-3 "반올림"을 따른다 → QA는 53만원을 정답으로 본다.
- 실패(`navigator.clipboard` 불가): 버튼 아래 읽기전용 `<textarea>`에 텍스트를 넣고 전체 선택 + "복사가 안 되면 위 문구를 길게 눌러 복사하세요."
- 공유 API(`navigator.share`)는 쓰지 않는다(범위 최소화).

#### 결과 이후 상태

- 결과 표시 후 아무 입력이나 바뀌면 결과 카드에 `.is-stale`: 카드 투명도 0.5 + 상단 띠 "입력값이 바뀌었어요. 다시 계산해 주세요." + 계산하기 버튼 라벨 "다시 계산하기". 자동 재계산 안 함(`calc_complete` 중복 방지).

### 2-6. FAQ (SEO 겸용, 7개, `<details>` 아코디언, 첫 항목만 기본 펼침)

섹션 제목 H2: "자주 묻는 질문". 각 질문은 `<summary><h3>…</h3></summary>`. 아래 질문·답 텍스트가 JSON-LD `FAQPage`와 같아야 한다.

1. `id="faq-threshold"` **Q. 신용카드 소득공제 25% 문턱이 뭔가요?**
   A. 카드 소득공제는 1년 동안 쓴 금액이 총급여의 25%를 넘어야 그 넘은 부분부터 공제됩니다. 예를 들어 총급여가 5,000만원이면 1,250만원까지는 신용카드든 체크카드든 공제가 0원이고, 그 위로 쓴 금액에 신용카드 15%, 체크카드·현금영수증 30%, 전통시장·대중교통 40% 공제율이 적용됩니다.

2. `id="faq-order"` **Q. 체크카드로 언제 바꿔야 하나요? 결제 순서가 중요한가요?**
   A. 세법상 결제 순서는 상관없습니다. 25% 문턱은 실제로 쓴 순서가 아니라 공제율이 낮은 신용카드 사용액부터 채운 것으로 계산하기 때문에, 1년 합계만 같으면 공제액도 같습니다. "문턱까지는 신용카드, 넘은 뒤엔 체크카드"라는 조언은 신용카드 할인·적립과 전월 실적 조건 때문이에요. 그래서 이 계산기는 남은 두 달 지출 전체를 신용카드로 쓸 때와 체크카드로 쓸 때를 비교합니다.

3. `id="faq-hometax"` **Q. 홈택스 연말정산 미리보기 금액은 어떻게 넣나요?**
   A. 홈택스 '연말정산 미리보기'에서 1~9월 결제수단별 사용액(신용카드, 체크카드·현금영수증, 전통시장, 대중교통)을 확인하세요. 10월 사용분은 카드사 앱에서 확인해 더하고, 전통시장·대중교통 금액은 신용·체크 칸에서 빼서 선택 칸에 따로 넣으면 됩니다. 미리보기 서비스는 예년에 11월 초에 열렸고, 2026년 오픈일은 아직 확인하지 못했습니다.

4. `id="faq-limit"` **Q. 2026년 신용카드 소득공제 한도는 얼마인가요?**
   A. 기본 한도는 총급여 7천만원 이하 300만원, 초과 250만원입니다. 2026년 1월 1일부터 20세 이하 자녀 등이 있으면 7천만원 이하는 1명 350만원·2명 이상 400만원, 초과는 1명 275만원·2명 이상 300만원으로 늘었습니다. 기본 한도를 넘으면 전통시장·대중교통(7천만원 이하는 문화비 포함) 공제분이 추가 한도(7천만원 이하 300만원, 초과 200만원)까지 더 인정됩니다.

5. `id="faq-excluded"` **Q. 이 계산에서 빠진 항목은 무엇인가요?**
   A. 소비증가분 특례(2026년 사용분에는 적용되지 않음), 도서·공연·영화·체육시설 문화비의 별도 공제율, 소득공제 종합한도는 계산에 넣지 않았습니다. 세금·공과금, 아파트관리비, 통신비, 보험료, 해외 사용분처럼 원래 공제 대상이 아닌 지출은 입력에서 빼 주세요.

6. `id="faq-refund"` **Q. 소득공제가 50만원 늘면 세금도 50만원 돌려받나요?**
   A. 아닙니다. 소득공제는 세금을 매기는 소득을 줄여 주는 것이라, 실제로 줄어드는 세금은 공제액 × 본인 세율(지방소득세 포함)입니다. 예를 들어 세율 15%(지방소득세 포함 16.5%) 구간이면 공제 50만원은 세금 약 8만 2천원입니다.

7. `id="faq-2027"` **Q. 신용카드 소득공제 폐지되나요? 2027년엔 뭐가 바뀌나요?**
   A. 현행법상 신용카드 소득공제 적용 기한은 2028년 12월 31일까지 연장돼 있습니다. 다만 2027년 사용분부터 대중교통 공제율과 추가 한도 등을 바꾸는 정부 개정안이 국회에 제출돼 있고, 2026년 10월 26일 확인 기준 국회를 통과하지 않은 미확정 안입니다. 정부 개정안대로 통과되면 무엇이 달라지는지는 [2027 개정안 변경점(미확정)](/2027-card-deduction-changes)에 정리했습니다. 이 계산기는 현행 규칙만 사용합니다.

> FAQ 6의 세율 예시: 500,000 × 16.5% = 82,500원 → "약 8만 2천원". 세율 구간 수치는 예시이며 숫자 단정은 이 한 줄만 쓴다(개발자 수정 금지).

### 3-3. Gumroad 버튼 동작

- 링크: `https://<seller>.gumroad.com/l/<permalink>?wanted=true&utm_source=…&utm_medium=…&utm_campaign=…` — `wanted=true`로 상품 페이지 건너뛰고 결제 단계로.
- UTM: 랜딩 시 URL의 `utm_*` 3종을 `sessionStorage`에 저장(입력값이 아니므로 허용) → 버튼 href에 붙임. 없으면 `utm_source=organic&utm_medium=web&utm_campaign=card-deduction-2026`.
- `target="_blank" rel="noopener"` — 결과 화면을 잃지 않게 새 탭. 클릭 직후 버튼 라벨 2초간 "Gumroad 결제 창을 여는 중…" + `aria-busy="true"`, 이후 원복(새 탭이 막혀도 버튼이 죽지 않게).
- `checkout_click` 이벤트: `location` = `calc_cta` / `sheet_section` / `changes_page`, UTM만. 금액·입력값 금지.
- 구매 버튼 옆(같은 박스 안, 버튼 바로 아래)에 F-2가 없는 구매 버튼은 존재하지 않는다(3곳 모두).

### 3-4. 결제 완료·전달 (사이트 밖)

사이트는 결제 완료를 감지하지 않는다("결제 완료" 상태 = Gumroad 영수증). 운영자가 Gumroad에 넣을 내용:

- 상품명: "2027 가계부 + 카드공제 트래커 (구글 시트)"
- 커버 이미지 1280×720: OG 이미지 레이아웃 재사용(7장), 문구만 "2027 가계부 + 카드공제 트래커 / 구글 시트".
- 썸네일 600×600: 파비콘 심볼 + "2027 카드공제 트래커".
- 설명 하단 고정: F-1, F-2, F-3.
- 영수증(구매 후 안내, "Content" 영역) 문구: "구매해 주셔서 감사합니다. 첨부된 '사용 설명 PDF'를 열고 1페이지의 '사본 만들기' 버튼을 누르면 내 구글 드라이브에 시트가 생깁니다. 구글 계정 로그인이 필요해요. 문의: <운영자 이메일>"

설명 PDF(A4 세로 2쪽, 시트와 같은 색):
- 1쪽: 제목 / F-1 배너 / 큰 버튼형 링크 "사본 만들기 (구글 시트)" (`…/copy`) / 3단계 그림(로그인 → 사본 만들기 → 내 드라이브) / "링크를 다른 사람과 공유하지 말아 주세요."

## 9. 유료 구글 시트 디자인 (openpyxl로 xlsx 생성 → 구글 시트 가져오기)

### 9-1. 제작 규칙 (호환성)

- **Apps Script 금지, 수작업 서식 금지.** openpyxl이 쓴 그대로 구글 시트에서 가져오기 → 공개용 원본 → `/copy` 링크.
- 사용 함수 허용 목록: `IF, AND, OR, MIN, MAX, SUM, SUMIFS, ROUNDDOWN, ROUND, MONTH, TEXT, REPT, LEFT`. **금지**: `ARRAYFORMULA, LET, LAMBDA, IFS, XLOOKUP, FILTER, QUERY, SPARKLINE, INDIRECT`, 이름 정의 범위(named range), 구조화 표(Excel Table).
- 시트 이름은 공백 없이(`2026마무리` 등). 숫자로 시작하므로 수식에서 **항상 작은따옴표로 감싼다**: `'2027월별'!$D$17`.
- **조건부 서식은 같은 시트 셀만 참조**(구글 시트는 다른 시트 참조 불가). 다른 시트 값이 필요하면 숨긴 미러 셀을 같은 시트에 둔다.
- **데이터 유효성 목록은 인라인 문자열**(`"a,b,c"`, 255자 이내). 다른 시트 범위 참조 목록 금지.
- **체크박스 대신 드롭다운 토글**: 구글 시트 네이티브 체크박스는 xlsx로 만들 수 없고 엑셀 사본(완료조건 4)도 깨진다. 값 2개 드롭다운 `☐ 끔 — 현행 규칙(기본)` / `☑ 켬 — 정부 개정안 시나리오`로 체크박스를 표현하고, 판정은 `LEFT(셀,1)="☑"`.
- 자녀 수 드롭다운 값 `0,1,2`(2 = 2명 이상). 수식에서 `(셀+0)`로 숫자화(텍스트로 들어와도 안전).
- 금액 셀 숫자 서식 `#,##0`, 퍼센트 `0%`. 날짜 `yyyy-mm-dd`. 글꼴은 지정하지 않는다(구글 기본 글꼴), 크기 10, 제목 14 bold.

- 시트 보호는 걸지 않는다(가져오기 시 유실). 색으로 입력/계산을 구분하고 "노란 칸만 입력하세요"로 안내.
